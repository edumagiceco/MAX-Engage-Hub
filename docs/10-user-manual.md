# User Manual

## 1. 문서 목적

이 문서는 현재 구현된 `MAX Engage Hub`를 실제로 어떻게 실행하고, 어떻게 운영해야 하는지 쉽게 설명하는 사용 매뉴얼이다.

대상 독자는 아래와 같다.

- 운영 담당자
- 세일즈/상담 담당자
- 내부 관리자
- 개발 환경을 처음 세팅하는 사용자

중요:

- 이 문서는 `현재 구현된 범위`를 기준으로 작성했다.
- 아직 구현되지 않은 `교육 운영`, `프로젝트 운영`, `메일링 자동화`는 이 문서의 사용 범위에 포함하지 않는다.
- 현재 사용 가능한 범위는 `리드 수집`, `고객 관리`, `진단/추천`, `태그`, `사례 라이브러리`다.

## 2. 현재 할 수 있는 일

현재 프로젝트에서 바로 가능한 기능은 아래다.

- 퍼블릭 폼 4종 제출
  - 일반 문의
  - 교육 문의
  - AX 진단 요청
  - AX 맞춤 추천 요청
- 이메일 기준 고객 중복 병합
- 고객 활동 이력 저장
- 관리자 로그인
- 관리자 인박스 확인
- 고객 목록 검색
- 고객 상세 확인
- 고객 상태 변경
- 운영 메모 추가
- 후속 액션 일정 추가
- 진단 결과와 추천 결과 자동 생성
- 고객 태그 자동/수동 관리
- 사례 라이브러리 등록 및 검색
- 고객 상세에서 관련 사례 추천 보기

## 3. 빠른 시작

### 3.1 로컬에서 실행하기

아래 순서대로 실행하면 된다.

1. 환경파일 생성

```bash
cp .env.example .env
```

2. 앱 키 생성

```bash
php artisan key:generate
```

3. 데이터베이스 설정

- MySQL을 사용할 경우 `.env`의 아래 값을 수정한다.
  - `DB_CONNECTION=mysql`
  - `DB_HOST`
  - `DB_PORT`
  - `DB_DATABASE`
  - `DB_USERNAME`
  - `DB_PASSWORD`

4. 마이그레이션과 시드 실행

```bash
php artisan migrate --seed
```

5. 개발 서버 실행

```bash
php artisan serve
```

6. 브라우저에서 접속

- 홈: `http://127.0.0.1:8000`
- 관리자 로그인: `http://127.0.0.1:8000/login`

### 3.2 기본 관리자 계정

`.env.example` 기준 기본 시드 계정은 아래다.

- 이메일: `admin@example.com`
- 비밀번호: `ChangeMe1234!`

운영 환경에서는 반드시 바꿔야 한다.

## 4. 화면 구성 이해하기

현재 프로젝트는 크게 2개의 영역으로 나뉜다.

### A. 퍼블릭 영역

누구나 접근 가능한 폼 화면이다.

- 홈 `/`
- 일반 문의 `/forms/contact`
- 교육 문의 `/forms/education`
- AX 진단 `/forms/diagnosis`
- AX 맞춤 추천 `/forms/recommendation`

### B. 관리자 영역

로그인 후 접근 가능한 내부 운영 화면이다.

- 관리자 로그인 `/login`
- 인박스 `/admin/inbox`
- 고객 목록 `/admin/customers`
- 고객 상세 `/admin/customers/{id}`
- 사례 라이브러리 `/admin/cases`

## 5. 퍼블릭 폼 사용 방법

### 5.1 홈 화면

홈 화면에서는 각 퍼블릭 폼으로 이동할 수 있다.

사용 목적:

- 외부 사용자에게 링크를 전달
- 테스트 시 각 폼 화면 바로 진입

### 5.2 일반 문의 폼

사용 상황:

- 서비스 소개 요청
- 상담 요청
- 기본 문의 접수

입력 추천 항목:

- 이름
- 이메일
- 회사명
- 한 줄 요약
- 상세 내용

저장 결과:

- 신규 고객이면 고객 레코드 생성
- 기존 고객이면 같은 이메일 기준으로 기존 고객에 활동 추가
- 활동 타입: `contact_submitted`

### 5.3 교육 문의 폼

사용 상황:

- 교육 프로그램 문의
- 사내 워크숍 문의
- 교육 견적 요청

저장 결과:

- 활동 타입: `education_inquiry_submitted`
- 최근 유입 경로: `education_form`

### 5.4 AX 진단 폼

사용 상황:

- 현재 AX 도입 수준을 진단받고 싶은 경우
- 현재 병목과 도입 단계를 함께 남기고 싶은 경우

추가 입력 항목:

- 관심 영역
- 현재 단계
- 관련 팀 규모

저장 결과:

- 활동 타입: `diagnosis_completed`
- 진단 결과 저장
- 추천 결과 자동 생성
- 관련 태그 자동 생성

### 5.5 AX 맞춤 추천 폼

사용 상황:

- 어떤 교육/컨설팅/솔루션이 맞는지 먼저 추천받고 싶은 경우

저장 결과:

- 활동 타입: `recommendation_requested`
- 추천 결과 자동 생성
- 관련 태그 자동 생성

## 6. 고객 병합 규칙

현재 프로젝트의 고객 병합 기준은 단순하다.

- 1순위 기준은 `이메일`
- 같은 이메일이면 기존 고객에 연결
- 다른 이메일이면 새 고객 생성

즉, 같은 사람이 `일반 문의`와 `AX 진단`을 각각 제출해도 이메일이 같으면 한 고객으로 관리된다.

## 7. 관리자 로그인 방법

1. `/login`으로 이동
2. 관리자 이메일 입력
3. 비밀번호 입력
4. 로그인 버튼 클릭

로그인 후 첫 화면은 `인박스`다.

## 8. 인박스 사용 방법

경로:

- `/admin/inbox`

인박스 화면에서 볼 수 있는 것:

- `new` 상태 고객 수
- `in_review` 상태 고객 수
- `contacted` 상태 고객 수
- 전체 고객 수
- 최근 리드 목록
- 최근 활동 제목
- 최근 유입 경로

인박스를 볼 때의 기본 해석:

- `new`: 아직 운영자가 손대지 않은 신규 리드
- `in_review`: 내용을 보고 검토 중인 리드
- `contacted`: 이미 연락한 리드
- `nurturing`: 바로 전환되진 않지만 관리 중인 리드

권장 사용 방법:

1. 인박스에서 신규 고객을 확인
2. 고객 이름 클릭
3. 고객 상세에서 진단/추천/태그/사례를 확인
4. 메모와 후속 액션 추가
5. 상태를 적절히 변경

## 9. 고객 목록 사용 방법

경로:

- `/admin/customers`

할 수 있는 일:

- 이름 검색
- 이메일 검색
- 회사명 검색
- 상태별 필터링
- 최근 접점 확인

이 화면은 전체 고객 디렉토리다.

권장 사용 상황:

- 과거 고객 검색
- 같은 회사 고객 찾기
- 특정 상태만 모아 보기

## 10. 고객 상세 사용 방법

경로:

- `/admin/customers/{id}`

고객 상세는 현재 프로젝트의 핵심 운영 화면이다.

### 10.1 기본 정보 영역

여기서 확인하는 정보:

- 연락처
- 직책
- 최근 유입 경로
- 마케팅 동의 여부
- 현재 상태

### 10.2 진단 및 추천 요약 영역

이 영역은 `AX 진단` 또는 `AX 맞춤 추천`이 들어온 고객에게 특히 중요하다.

표시 항목:

- 진단 점수
- maturity level
- 진단 요약
- 주요 pain point
- 추천 타입
- 추천 사유
- 다음 액션 제안

운영자가 보는 관점:

- 이 고객이 지금 교육이 먼저 필요한지
- 컨설팅으로 넘어가야 하는지
- RAG/OCR/자동화 중 어디에 관심이 있는지
- 다음 상담에서 무엇을 제안해야 하는지

### 10.3 고객 태그 영역

태그는 자동으로 붙기도 하고 수동으로 추가할 수도 있다.

예시:

- `rag_interest`
- `ocr_interest`
- `automation_interest`
- `education_interest`
- `paid_diagnosis_candidate`
- `high_intent`

사용 방법:

1. 태그 입력창에 값 입력
2. `태그 추가` 클릭
3. 잘못된 태그는 `×` 버튼으로 제거

권장 규칙:

- 같은 뜻의 태그를 여러 방식으로 만들지 않는다.
- 운영팀 내부에서 태그 사전을 정해서 사용한다.

### 10.4 상태 변경 영역

고객 상태는 드롭다운에서 변경한다.

권장 흐름:

- `new`
- `in_review`
- `contacted`
- `meeting_scheduled`
- `proposal`
- `won`
- `lost`
- `nurturing`

상태를 바꾸면 활동 타임라인에 변경 이력이 남는다.

### 10.5 운영 메모 영역

이 영역에는 상담 준비를 위한 운영 메모를 남긴다.

적기 좋은 내용:

- 통화 전 확인 포인트
- 제안 시 참고할 이슈
- 내부 담당자 메모
- 다음 미팅에서 확인할 질문

메모를 저장하면 활동 이력에도 반영된다.

### 10.6 후속 액션 영역

후속 액션은 일정이 있는 다음 행동을 등록할 때 사용한다.

예시:

- 첫 미팅 일정 확정
- 유사 사례 정리 후 발송
- 제안서 초안 전달
- 교육 일정 후보 전달

입력 항목:

- 액션 제목
- 예정일
- 메모

### 10.7 활동 타임라인 영역

고객과 관련된 주요 이벤트가 시간순으로 쌓인다.

예시:

- 폼 제출
- 진단 요약 생성
- 추천 생성
- 메모 추가
- 상태 변경
- 후속 액션 등록
- 태그 추가/삭제

이 화면을 보면 "이 고객에게 무슨 일이 있었는지"를 빠르게 파악할 수 있다.

### 10.8 관련 사례 영역

고객의 최신 추천 타입과 연결되는 사례를 보여준다.

예시:

- 추천 타입이 `rag`이면 RAG 관련 사례 우선 표시
- 추천 타입이 `workflow_automation`이면 자동화 사례 우선 표시

이 영역은 첫 상담 준비에 바로 쓰면 된다.

## 11. 진단 결과를 읽는 방법

현재 구현은 고정 규칙 기반이다.

즉, AI 모델이 아니라 입력값을 바탕으로 점수와 추천을 계산한다.

### 11.1 진단 점수

점수는 아래 요소를 바탕으로 계산된다.

- 현재 단계
- 팀 규모
- 관심 영역
- 상세 입력 길이

### 11.2 maturity level

점수에 따라 아래 단계 중 하나로 분류된다.

- `starter`
- `emerging`
- `scaling`
- `advanced`

실무 해석 예시:

- `starter`: 교육/기초 정리가 먼저 필요한 경우가 많음
- `emerging`: 파일럿 또는 부서 단위 정리가 필요한 단계
- `scaling`: 확산 단계, 실행 설계가 중요
- `advanced`: 자동화/고도화 과제로 넘어가기 쉬움

### 11.3 추천 타입

현재 추천 타입은 아래 중 하나다.

- `education`
- `consulting`
- `rag`
- `ocr`
- `workflow_automation`

추천 타입은 입력된 관심 영역이 명확하면 그 값을 우선 사용한다.

## 12. 사례 라이브러리 사용 방법

경로:

- `/admin/cases`

### 12.1 사례 등록

입력 항목:

- 제목
- 솔루션 타입
- 산업
- 부서
- 문제 정의
- 요약
- 성과/결과
- 지표
- 상태

지표 입력 예시:

```text
준비시간: 40% 단축
응답정확도: 90%
```

이렇게 입력하면 화면에서 작은 지표 태그로 보인다.

### 12.2 사례 검색

검색 기준:

- 제목
- 문제
- 요약
- 산업
- 부서
- 솔루션 타입
- 상태

권장 사용 방법:

1. 고객 상세에서 추천 타입 확인
2. 사례 라이브러리로 이동
3. 같은 솔루션 타입 또는 산업으로 검색
4. 상담에 바로 쓸 사례를 선택

## 13. 기본 운영 시나리오

### 시나리오 A. 일반 문의가 들어왔을 때

1. 외부 사용자가 일반 문의 폼 제출
2. 운영자는 인박스에서 신규 리드 확인
3. 고객 상세로 이동
4. 메모 작성
5. 후속 액션 등록
6. 상태를 `in_review` 또는 `contacted`로 변경

### 시나리오 B. AX 진단이 들어왔을 때

1. 사용자가 진단 폼 제출
2. 고객 상세에서 진단 요약 확인
3. 추천 타입 확인
4. 관련 사례 확인
5. 상담 준비 메모 추가
6. 후속 미팅 일정 등록

### 시나리오 C. 상담 전에 사례를 준비할 때

1. 고객 상세에서 추천 타입 확인
2. 관련 사례 영역 먼저 확인
3. 더 필요한 경우 사례 라이브러리로 이동
4. 산업/부서/솔루션 기준으로 검색
5. 메모에 사용할 사례 제목과 포인트를 남김

## 14. 운영자가 매일 보면 좋은 화면

### 아침에 먼저 볼 화면

- `/admin/inbox`

이유:

- 신규 리드 누락 방지
- 상태별 현황 파악

### 고객 확인이 필요할 때

- `/admin/customers`

이유:

- 이름/이메일/회사명으로 빠른 검색 가능

### 상담 준비 직전

- `/admin/customers/{id}`

이유:

- 진단/추천/태그/메모/후속 액션/사례를 한 번에 볼 수 있음

### 사례 업데이트가 필요할 때

- `/admin/cases`

## 15. 샘플 데이터

로컬 또는 테스트 환경에서 `php artisan migrate --seed`를 실행하면 아래가 자동 생성된다.

- 기본 관리자 계정 1개
- 샘플 사례 몇 건

이 샘플 사례는 개발 중 화면 확인용이다.

운영 환경에서는 실제 사례로 교체하는 것이 좋다.

## 16. 자주 생길 수 있는 문제와 해결 방법

### 문제 1. 로그인 페이지는 열리는데 로그인되지 않는다

확인할 것:

- `.env`의 시드 관리자 이메일
- `.env`의 시드 관리자 비밀번호
- `php artisan migrate --seed`를 다시 실행했는지

### 문제 2. 폼 제출 후 고객이 안 보인다

확인할 것:

- 폼 제출 시 validation error가 없는지
- DB 연결이 정상인지
- 같은 이메일로 이미 고객이 있어서 기존 고객에 병합된 것은 아닌지

### 문제 3. 고객 상세에 진단/추천이 안 보인다

가능한 이유:

- 일반 문의/교육 문의만 들어온 경우
- 진단/추천 요청이 아닌 경우

정상이다.

진단/추천 영역은 해당 요청이 들어왔을 때만 채워진다.

### 문제 4. 사례가 안 보인다

확인할 것:

- 사례가 `approved` 상태인지
- 고객의 최신 추천 타입과 사례의 `solution_type`이 맞는지

### 문제 5. 로컬에서 페이지는 뜨는데 DB 에러가 난다

확인할 것:

- `.env`의 DB 설정
- MySQL 서버 실행 여부
- `php artisan migrate --seed` 실행 여부

## 17. 닷홈 무료호스팅 운영 시 주의사항

닷홈 무료호스팅에 배포할 경우 아래를 특히 주의한다.

- `queue worker`를 전제로 쓰지 않는다.
- 자동 메일 발송을 전제로 쓰지 않는다.
- 업로드 파일은 작게 유지한다.
- 로그 파일이 커지지 않게 관리한다.
- 서버에서 빌드하는 대신 로컬에서 준비 후 업로드하는 전략이 안전하다.
