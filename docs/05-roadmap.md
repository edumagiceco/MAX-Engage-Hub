# Roadmap

## Phase 1. Lead Intake Foundation

목표는 `고객 유입을 놓치지 않는 것`이다.

개발 항목:

- 문의/교육/진단/추천 폼 수집 API
- 고객 기본 테이블
- 활동 이력 저장
- 관리자 인박스
- 고객 상세 기본 화면

완료 기준:

- 모든 폼이 한 DB로 저장된다.
- 신규 리드를 관리자에서 확인할 수 있다.

## Phase 2. Diagnosis And Consultation Support

목표는 `첫 상담 준비 시간을 줄이는 것`이다.

개발 항목:

- 진단 결과 저장
- 규칙 기반 추천 저장
- 고객 태그 관리
- 사례 라이브러리 등록/검색

완료 기준:

- 상담자가 고객 상세에서 진단과 추천을 본다.
- 관련 사례를 검색해 바로 활용할 수 있다.

## Phase 3. Education Operations

목표는 `교육 진행과 결과물을 남기는 것`이다.

개발 항목:

- 교육 프로그램 등록
- 교육 회차 관리
- 참여자 관리
- 교육 결과물 저장
- 후속 액션 기록

완료 기준:

- 교육 회차별 참여 현황을 볼 수 있다.
- 결과물이 고객 또는 회사와 연결되어 저장된다.
- 교육 종료 후 후속 상담/제안으로 이어질 수 있다.

## Phase 4. Project Delivery Tracking

목표는 `교육 이후 컨설팅/솔루션 프로젝트 흐름을 기록하는 것`이다.

개발 항목:

- 프로젝트 생성
- 프로젝트 유형 관리
- 진행 메모 및 중간 산출물 저장
- 프로젝트 종료 요약 저장

완료 기준:

- 교육 이후 후속 프로젝트를 등록할 수 있다.
- 프로젝트별 진행 상태와 종료 결과를 확인할 수 있다.

## Phase 5. Case Capture And Reuse

목표는 `교육과 프로젝트 결과를 영업 자산으로 바꾸는 것`이다.

개발 항목:

- 사례 후보 등록
- 사례 승인/전환
- 사례 검색
- 상담/제안 연결

완료 기준:

- 교육 결과물이나 프로젝트 결과를 사례 후보로 등록할 수 있다.
- 승인된 사례를 상담에서 바로 검색해 활용할 수 있다.

## Phase 6. Blog Mailing Loop

목표는 `콘텐츠를 실제 nurture 자산으로 쓰는 것`이다.

개발 항목:

- 블로그 글 등록/연동
- 메일 발송 화면
- 수신 동의 필터링
- 오픈/클릭 webhook 반영

완료 기준:

- 블로그 글을 선택해 메일을 발송할 수 있다.
- 고객별 메일 반응 이력이 저장된다.

## Phase 7. Performance Dashboard

목표는 `무엇이 실제로 리드와 상담을 만드는지 보는 것`이다.

개발 항목:

- 채널별 리드 현황
- 상태 전환 현황
- 교육 운영 성과
- 프로젝트 운영 성과
- 사례 등록 및 활용 현황
- 블로그/메일 성과

완료 기준:

- 운영자가 기본 성과를 주간 단위로 볼 수 있다.

## 우선순위 원칙

1. 먼저 저장한다.
2. 그 다음 보이게 한다.
3. 그 다음 분류한다.
4. 마지막에 자동화한다.

이 순서를 지키면 MVP에서 과설계를 피할 수 있다.
